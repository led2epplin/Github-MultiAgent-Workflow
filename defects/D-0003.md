## 재현
A 하니스가 claim 한 티켓의 실행기가 도는 사이 임대가 만료되고 B 가 `tk claim` 으로 인계(push). A 실행기가 끝나면 validate → `t/<T>` 브랜치 push → PR → sync_main → `tk move <T> review` — B 가 claim 한 티켓이 A 의 결과로 review 에 간다. 실행기가 오래 돌아도 A 는 임대를 연장하지 않아 만료가 그대로 난다.

## 원인
1.1.0 의 `engine/build/run_ticket.sh` 는 claim push 뒤로는 티켓 claim 을 다시 보지 않았다(실행기 → validate → push → 상태 전이). `tk renew` 는 있었지만 하니스가 부르지 않았다.

## TC
`bash tests/defects/D-0003.sh <임시폴더> [대상 엔진 저장소]` — 가짜 gh(PR 경로)·기다리는 시험용 실행기로 두 경우: ① 실행기 대기 중 임대 만료 → B `tk claim` 인계 → A 재개 ② 실행 중 임대 연장(2초마다) 확인 → B 가 인계하면 연장이 거절돼 실행기 종료. 둘 다 원격 티켓 doing·claim B 유지, A 의 review 전이·`t/<T>` push 없음.

## 수정
claim 세대 = `claim.by|claim.at`(claim push 직후 기록). 실행기 뒤·검증 뒤(결과 확정 전)·반려 전에 원격 main 과 대조(`still_mine`), PR 뒤·반려·실행기 장애 되돌림의 상태 전이 직전에 다시 대조 — 다르면 상태를 바꾸지 않고 작업물은 `lost/<T>-<세션>` 브랜치로만. 실행기는 배경 실행 + `renew_loop`(임대 절반마다, 별도 worktree 에서 `tk renew` → main push; `MAWF_RENEW_SEC` 로 바꿈) — 원격 claim 이 남의 것이면 실행기 프로세스 그룹을 끝낸다.
