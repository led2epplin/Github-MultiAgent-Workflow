## 재현
같은 ready 티켓을 두 하니스(A·B)가 동시에 집는다(A 의 claim push 가 B 의 claim 커밋 직후에 나가게 pre-push 훅으로 순서 고정). B 의 `push_main` 이 push 실패 → `git pull --rebase` → `tickets/doing/<T>.yaml` 충돌로 rebase 가 멈춘 채 실패 반환 → 「claim push 거절」 로 넘어가지만 `.git/rebase-merge` 가 남는다. `sync_main` 의 `reset --hard` 는 rebase 상태를 거두지 않는다. 마지막 status push 경합도 같은 경로.

## 원인
`build/run_ticket.sh` 의 `push_main` 하나가 claim·review·reject·status 를 모두 올리고, push 실패 시 rebase 재시도를 하되 rebase 실패를 `--abort` 하지 않았다. claim 은 재시도 대상이 아니다 — 먼저 push 된 claim 만 살아야 한다(선점 = push 성공).

## TC
`bash tests/defects/D-0001.sh <임시폴더> [대상 엔진 저장소]` — 로컬 bare 원격 하나에 소비 저장소 클론 A·B, DRY_RUN·NO_PR 하니스를 동시에 돌린다. 원격 claim 커밋 1개(A), B 는 「claim push 거절」·exit 0, A·B 모두 rebase 잔여 없음, B 가 경합 뒤 다음 push 가능.

## 수정
`push_claim`(재시도 없음) 분리, `push_main` 의 rebase 실패는 `git rebase --abort`, `sync_main` 이 먼저 진행 중 rebase·merge 를 거둔다(engine/build/run_ticket.sh).
